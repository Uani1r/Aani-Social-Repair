# اختبار توقيع ImageKit قبل التفعيل (أداة مؤقتة)

أداة تشخيص مؤقتة تتحقق من أن مسار ImageKit حقيقي يخصّ المستخدم الحالي يمكن توقيعه
عبر `/api/media/imagekit-sign`، وأن الرابط الموقّع يُفتح ويعيد **HTTP 200**.

الغرض: التأكد أن الخادم و`aani_can_read_media_object` والمفتاح الخاص جاهزون **قبل**
تفعيل `VITE_IMAGEKIT_SIGNED_URLS` أو ضبط ImageKit على Restricted access، فلا تنكسر
الوسائط في الإنتاج بلا سبب معروف.

## الملفات

| الملف | الدور |
|---|---|
| `src/components/ImageKitSignDiagnostics.tsx` | الواجهة: زر عائم + لوحة النتائج |
| `src/lib/imagekitSignCheck.ts` | المنطق: جمع المسارات، طلب التوقيع، فتح الرابط |
| `src/App.tsx` | سطران: الاستيراد والعنصر داخل فرع `user ?` فقط |
| `docs/IMAGEKIT_SIGN_TEST_AR.md` | هذا المستند (اختياري، يُحذف معها) |

## 1) ما تفعله بالضبط

1. **جمع المسارات** — قراءة فقط وبجلسة Supabase الحالية، ومحدودة بـ`user_id` نفسه:
   - `profiles.avatar_url` و`profiles.cover_url`
   - أول 5 صفوف من `posts.media_url` و`posts.media_urls`
   - أول 5 صفوف من `stories.media_url` و`stories.thumbnail_url`

   ما ليس رابط ImageKit (مثل مسارات Supabase Storage القديمة) **يُتخطى** ولا يظهر
   كمرشّح. ويُقبل أيضاً مسار يدوي: رابط ImageKit كامل أو مسار يبدأ بـ`/`.

2. **طلب التوقيع** — نفس شكل الطلب المستخدم في `src/lib/mediaAccess.ts`:
   `GET /api/media/imagekit-sign?path=…` بترويسة `Authorization: Bearer <access token>`.
   الخادم يتحقق من الجلسة، ثم من `aani_can_read_media_object`، ثم يوقّع بالمفتاح
   الخاص ويعيد `{ success, url, expire }`.

3. **فتح الرابط الموقّع** — `fetch(url, { method: 'HEAD' })` أولاً، و`GET` إن رفض
   المضيف `HEAD`، مع `credentials: 'omit'` (لا كوكي جلسة يُرسل إلى ImageKit).
   **HTTP 200 = النجاح**.

4. **العرض** — سطران لكل مرشّح: «التوقيع» و«الفتح»، مع سبب الفشل بكلمات مفهومة.

## 2) ما لا تفعله

- لا تفعّل `VITE_IMAGEKIT_SIGNED_URLS` ولا `VITE_IMAGEKIT_PRIVATE_UPLOADS` ولا
  `IMAGEKIT_SIGNED_URLS_ENABLED` ولا `IMAGEKIT_PRIVATE_UPLOADS`. الاختبار يعمل
  وقيمة التوقيع `false`.
- لا تغيّر أي إعداد في ImageKit أو Render أو Supabase، ولا ترفع أي ملف
  بـ`isPrivateFile`، ولا تجعل أي ملف خاصاً.
- لا تكتب أو تعدّل أو تحذف أي صف في قاعدة البيانات، ولا تحذف أي ملف.
- لا تعرض المفتاح الخاص ولا `access token` ولا الرابط الموقّع نفسه — تعرض حالة
  HTTP وسبب الفشل فقط. الرابط الموقّع اعتماد مؤقت لساعة، فلا يُعرض ولا يُنسخ ولا
  يُخزَّن خارج الذاكرة.

## 3) كيف تُستخدم

1. افتح التطبيق من خدمة Render (`aani-social`) — **لا** من معاينة Netlify: تلك لا
   تخدم `/api`، فسيفشل الطلب بـ404 من مضيف ثابت.
2. سجّل الدخول بحساب له وسائط فعلية على ImageKit (صورة ملف أو منشور).
3. اضغط الزر العائم «تشخيص التوقيع» أسفل يسار الشاشة. يظهر **فقط** للمستخدم
   المسجّل، لأن `App.tsx` يركّبه داخل فرع `user ?` وحده.
4. «جمع مساراتي»، ثم «اختبر» بجانب أي مسار، أو «اختبر الكل» (متسلسل عمداً).

## 4) تفسير النتائج

| النتيجة | المعنى |
|---|---|
| التوقيع `200` + الفتح `200` | المسار كامل: التوقيع أُنشئ وImageKit قبله. |
| التوقيع `403` | `aani_can_read_media_object` رفضت المسار لهذا المستخدم: المسار لا يخصّ محتوى يقرأه، أو ترحيل قرار الوسائط غير مطبَّق. |
| التوقيع `401` | الجلسة منتهية أو غير صالحة — أعد تسجيل الدخول. |
| التوقيع `503` | `IMAGEKIT_URL_ENDPOINT` أو `IMAGEKIT_PRIVATE_KEY` أو `SUPABASE_*` ناقص على الخدمة. |
| التوقيع `400` | المسار غير مقبول على الخادم (ليس مساراً مطلقاً نظيفاً). |
| الفتح `401`/`403` | التوقيع أُنشئ لكن ImageKit رفضه: غالباً المفتاح الخاص لا يطابق الـendpoint. |
| الفتح `404` | الصف في القاعدة يشير إلى مسار لا ملف له على ImageKit. |
| «تعذّر قراءة حالة الاستجابة» | المتصفح منع قراءة الحالة (CORS) أو انقطعت الشبكة — التوقيع نفسه نجح. |

**قبل التفعيل** يكون الفتح `200` على أي حال، لأن ملفات ImageKit الحالية عامة ولم
تُضبط على Restricted access. بعد التفعيل يجب أن يبقى `200` عبر الأداة، وأن يصبح
الرابط **بلا** توقيع مرفوضاً — وهذا يُختبر يدوياً خارج التطبيق، لا هنا.

1. في `src/App.tsx`:
   - احذف السطر: `import ImageKitSignDiagnostics from '@/components/ImageKitSignDiagnostics';`
   - احذف التعليق والعنصر `<ImageKitSignDiagnostics userId={user.id} />`.
   - أعِد `<Shell …>` مكانه المباشر داخل `{user ? ( … ) : ( … )}` وأزل الغلاف
     `<>` و`</>` اللذين أُضيفا حوله. بعد الحذف يعود الملف مطابقاً لما كان عليه
     قبل هذا الفرع تماماً.
2. احذف الملفين:
   - `src/components/ImageKitSignDiagnostics.tsx`
   - `src/lib/imagekitSignCheck.ts`
3. احذف هذا المستند.

لا تغيير آخر: لا متغيرات بيئة، ولا تعديل على أي ملف قائم آخر، ولا أثر في قاعدة
البيانات أو ImageKit — فحذف الملفات الثلاثة يعيد الحالة كما كانت.
