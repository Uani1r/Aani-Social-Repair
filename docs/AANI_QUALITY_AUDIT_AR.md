# AANI Quality Audit — البنية الأساسية

هذا الملف يوثّق الأساس الآلي لفحص جودة واجهة تطبيق آني (`artifacts/aani-social`).
الهدف منه أن يكون نقطة انطلاق ثابتة تُبنى عليها فحوص أعمق لاحقاً، لا أن يحل
محل اختبار يدوي على جهاز حقيقي.

## ما أُضيف في هذه الدفعة

| الملف | الدور |
|---|---|
| `playwright.config.ts` | إعداد Playwright: ثلاثة مشاريع فحص، تشغيل خادم Vite تلقائياً، تقارير JSON وHTML. |
| `e2e/utils/network.ts` | عزل الشبكة: منع كل طلب غير محلي (Supabase، خطوط Google، ImageKit …). |
| `e2e/aani-boot.spec.ts` | فحص الإقلاع: الإطار العربي RTL، تركيب React داخل `#root`، غياب أخطاء JavaScript البرمجية. |
| `e2e/aani-layout.spec.ts` | فحص التخطيط: لا تمرير أفقي، ولقطة شاشة مرجعية لكل بيئة. |
| `scripts/quality-audit/report-ar.mjs` | توليد تقرير عربي RTL من نتائج JSON + ملخّص لـ GitHub Actions. |
| `.github/workflows/quality-audit.yml` | تشغيل الفحص تلقائياً على GitHub Actions ورفع التقرير كأثر (artifact). |

## البيئات المفحوصة

1. `chromium-desktop` — Chromium على مقاس سطح المكتب (1280×800).
2. `chromium-iphone` — محرك Chromium مع ملف جهاز iPhone 13.
3. `webkit-iphone` — محرك WebKit (محرك Safari) مع ملف جهاز iPhone 13.

WebKit هو أقرب محاكاة متاحة لمتصفح Safari على الآيفون، لكنه لا يغني عن
اختبار على جهاز حقيقي (خصوصاً السلوك الخاص بـ iOS: شريط العناوين، لوحة
المفاتيح، والإيماءات).

## كيف يعمل الفحص

1. يشغّل Playwright خادم Vite للتطبيق تلقائياً على المنفذ `4173` من داخل
   حزمة `@workspace/aani-social`.
2. كل اختبار يمنع أولاً كل الطلبات إلى نطاقات غير محلية، فلا يصل أي طلب إلى
   Supabase أو أي خدمة خارجية أثناء الفحص.
3. تُسجَّل النتائج في `quality-audit-results/results.json`، ويُبنى منها:
   - `quality-audit-results/report-ar.html` — تقرير عربي كامل.
   - `quality-audit-results/summary-ar.md` — ملخّص Markdown، ويُضاف تلقائياً
     إلى ملخّص تشغيل GitHub Actions.
4. يرفع سير العمل مجلد `quality-audit-results` كاملاً (تقرير + لقطات + تقرير
   Playwright HTML) كمُخرَج قابل للتنزيل.

يمكن تشغيل الفحص على خادم قائم بدل تشغيل Vite محلياً عبر متغير البيئة
`AANI_BASE_URL`، وعندها يتجاهل Playwright خطوة تشغيل الخادم التلقائي.

## التشغيل المحلي

```bash
# مرة واحدة: تثبيت المتصفحات (Chromium + WebKit)
pnpm run audit:browsers

# تشغيل الفحص ثم توليد التقرير العربي
pnpm run audit
pnpm run audit:report
```

لعرض التقرير: افتح `quality-audit-results/report-ar.html` في المتصفح.

لتخطي تنزيل المتصفحات أثناء `pnpm install` (مفيد في بيئة محدودة الموارد):

```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 pnpm install
```

## ملاحظة عن ملف القفل

أُضيفت الاعتمادية `@playwright/test` (بنسخة مثبتة `1.49.0`) إلى
`devDependencies` في جذر مساحة العمل، لكن `pnpm-lock.yaml` لم يُحدَّث بعد
لأن هذا التغيير تم دون تشغيل مدير الحزم. لذلك يستخدم سير العمل
`pnpm install --no-frozen-lockfile` مؤقتاً.

**المطلوب محلياً مرة واحدة:** تشغيل `pnpm install` والالتزام بملف القفل
المحدَّث، ثم إزالة `--no-frozen-lockfile` من سير العمل.

## الحدود الحالية

- الفحص لا يتصل بـ Supabase ولا بأي خدمة خارجية، لذلك لا يغطي:
  تسجيل الدخول، الخلاصة، الرسائل، القصص، الرفع إلى التخزين، أو أي تدفق
  يحتاج بيانات حقيقية.
- لا توجد بعد اختبارات تدفقات (flows) أو اختبارات تسجيل دخول؛ البنية الحالية
  تتحقق من الإقلاع والتخطيط فقط.
- محاكاة iPhone في Chromium وWebKit ليست بديلاً عن جهاز iOS حقيقي.
- الفحص يعتمد على خادم Vite التطويري، وليس على نسخة إنتاج مبنية.
- لم تُشغَّل هذه الفحوصات ولا توليد التقرير عند إضافة هذه البنية؛ التحقق
  الفعلي يحدث في GitHub Actions أو عند تشغيلها محلياً.

## الخطوات القادمة المقترحة

1. تحديث ملف القفل محلياً وإزالة `--no-frozen-lockfile` من سير العمل.
2. إضافة اختبار تدفق تسجيل الدخول باستخدام بيئة Supabase مرحلية معزولة
   (لا الإنتاج) ومتغيرات سرية في GitHub.
3. إضافة فحوص تخطيط أعمق: أحجام أهداف اللمس، تداخل العناصر الثابتة،
   والتمرير داخل الحاويات.
4. تشغيل الفحص على نسخة إنتاج مبنية (`vite build` + `vite preview`) بدل
   خادم التطوير.
5. إضافة عتبة ثابتة لجودة الأداء (مثل حجم الحزمة) إلى التقرير.
